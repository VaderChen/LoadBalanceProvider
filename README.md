# Load Balance Provider

**繁體中文** | [English（舊版概覽）](README.en.md) | [日本語（舊版概覽）](README.ja.md) | [한국어（舊版概覽）](README.ko.md)

集中管理多個 LLM Provider，讓相容的應用程式、Codex 與 Agent 共用單一服務入口。透過 Web 管理介面查看負載、用量與帳號狀態，並依模型能力及可用容量安排請求。

## 功能特色

| 功能 | 使用價值 |
| --- | --- |
| 統一 API 入口 | 支援 OpenAI 相容 Chat Completions、Responses 與串流回應，方便既有工具接入。 |
| 多 Provider 與模型管理 | 集中設定來源、模型能力、併發上限與選擇策略，支援自動選擇或指定來源。 |
| 新回合用量均衡 | 在相同模型與用途的合格來源間，兼顧剩餘額度、目前負載及綁定數；不為均衡而移動既有回合。 |
| 對話配對與容量備援 | 優先保留原 Provider 與模型；容量失敗時，僅在內容尚未送出、歷史完整且未強制指定來源的條件下改用其他帳號。 |
| 有限重試與連線保活 | 等待期間維持心跳，遵守冷卻與總嘗試上限，避免同一請求在重連後反覆擴大重送。 |
| 服務統計 | 查看啟用來源、活躍請求、綁定數、反應時間與 Token 速度，支援工作階段及累計檢視。 |
| 用量與帳號管理 | 查看剩餘量、每日用量及每金鑰使用情形；ChatGPT／Codex OAuth 來源另提供重設與帳單功能。 |
| MCP 整合 | 讓支援 MCP 的工具查詢服務狀態或執行允許的操作，並可切換唯讀模式。 |
| 更新與恢復 | 部署 ZIP 支援管理頁面更新，保存可恢復的對話配對；另提供 DMG／MSI 桌面安裝方式。 |

## 管理介面

### Provider 與模型

新增來源後，設定連線、認證、模型與最大併發數，再啟用供請求使用。連線設定可收合，方便在較窄的畫面檢視其他帳號資訊。

每個 Provider 可在「每日停機（台北時間）」獨立設定開關、開始與結束時間。預設開關關閉、時段為每日 04:00–05:00，固定使用 `Asia/Taipei`，不受部署主機時區影響。支援跨午夜，開始時間包含在停機範圍內、結束時間不包含，起訖不可相同。

排程生效期間不接受該來源的新推論派送、測試對話與最小請求探測，也暫停背景用量更新；已送出的串流不強制中斷。時段結束自動恢復可派送資格，但不會改動手動停用狀態、清除冷卻或繞過原有回合綁定限制。帳號管理操作不屬於推論排程。設定存於各來源的 `downtime` 欄位（`enabled`、`start`、`end`），舊設定未提供時預設關閉。

自動選擇保留隨機、加權及任務路由策略。新回合選定模型後，會在相同模型、用途、權重與模型等級的合格來源間，兼顧剩餘額度、活躍負載及綁定數；條件相同時優先分給較久未獲配的來源。列表新增順序不會阻止均衡。過期或缺漏的用量不當成滿額或零額，額度窗口不同時不直接比較百分比。

已建立綁定的回合與明確指定來源的請求不因用量差距換帳號。既有長回合、不同任務大小及上游更新延遲仍可能造成差距，均衡會隨新回合逐步調整，不保證每個帳號消耗完全一致。Codex OAuth 的模型清單可向上游重新查詢，實際可用項目以帳號權限及查詢結果為準。

### 服務統計與用量

- 儀表板採緊湊排列，顯示 Provider 總數、啟用數、活躍請求與可使用量。
- 平均速度區列出反應時間、處理時間、Token 生成與輸出速度。
- 活躍模型區可查看各 Provider 的請求、綁定及併發情形。
- 用量暫時查不到時，保留已有的有效觀測；包含舊值時會標示，不把缺值當作滿額或零額。
- ChatGPT／Codex OAuth 優先向帳號用量 API 查詢，不再為背景用量更新發送模型請求；一般回應標頭仍會解析，作為查詢失敗或資料過期時的備援。
- 每日用量僅累積同一來源與額度窗口內可比較的消耗，數值回彈不重複扣量。帳號 API 已建立基準後，標頭備援只更新剩餘量展示，不再累積第二套消耗；缺少日初基準、來源切換或舊版資料會提示僅供參考，不回填缺漏或自動重算舊紀錄。

剩餘量是帳號配額觀測，不等於實際費用。即時比例、每日配額消耗與 Token 統計的口徑不同，不宜直接互相換算。

「含舊值」表示部分來源仍使用最後有效觀測，並非所有帳號的即時查詢結果。平均值可能在一段時間內不變，不能只依此判定服務停止更新。

帳號 API 約每三分鐘查詢一次，失敗後約一分鐘重新排程，同一來源不重複並行查詢；忙碌或網路延遲可能使實際完成較晚。用量明細可查看資料來源、上次查詢、成功時間、下次查詢及失敗狀態。帳號觀測超過六分鐘列為舊值，一般標頭來源採十二分鐘；顯示與選路採同一新鮮度標準。

API 回傳有效資料時優先採用；查詢失敗時使用較新的有效標頭備援，兩者皆無新資料則保留舊值。上游百分比仍可能延遲或以較粗的刻度更新，這不是逐次請求的即時計費表。

### 使用量限制重設

ChatGPT／Codex OAuth 來源可展開「使用量限制重設」卡片，查看可用次數及各張重設的到期時間，由使用者選擇要使用哪一張並確認。只有上游確認重設成功後，才更新對應用量狀態。

可用重設與資格依上游帳號回傳為準；沒有可用項目不代表查詢失敗，也不會自動購買或使用重設。

### 帳單列表

ChatGPT／Codex OAuth 來源的重設卡片下方提供可收合的「帳單列表」：

1. 預設不查詢、不顯示帳單資料。
2. 按右側「查詢」後顯示載入狀態。
3. 結果依新到舊列出日期、金額、付款狀態與下載按鈕，可繼續載入較早紀錄。
4. 「下載」開啟該筆帳單的 Stripe 頁面，再由該頁下載帳單或收據。

帳單僅供管理頁面登入查詢，不向一般 API 金鑰或 MCP 公開。查詢使用該 Provider 的 OAuth 認證；是否可取得資料仍取決於帳號權限與上游服務。帳單連結含私人存取資訊，請勿公開分享。

### 測試對話

導覽列的「測試對話」提供 Provider 與模型選擇，可使用管理登入測試多輪對話，查看串流文字及 Markdown 格式回覆。支援停止生成、複製訊息與清空；切換來源或模型會直接清空前文，不再顯示確認彈窗。

未啟用的來源也可進行測試，下拉選單會標示「未啟用」。測試不會啟用來源，也不會讓該來源加入正式代理的流量分配。

對話使用獨立診斷通道，每次只向所選來源送出一次請求，不經正式代理的排程、冷卻、重試或換帳號，也不將錯誤包裝成助理訊息。頁面顯示上游 HTTP 狀態、上游提供的 Request ID 與 Retry-After，並可展開「原始回應」查看收到的 JSON 或串流事件。未取得上游 HTTP 回應時，會明確標示代理端錯誤；上游的認證失敗不會被誤認為管理登入過期。

此功能仍透過本機服務連接上游；Codex 來源保留必要的認證與請求格式轉換，但上游回應不改寫。診斷不納入正式代理的請求統計，上游仍可能計費或扣除用量。每次最長等待 10 分鐘，頁面最多保留 2,000,000 字元原始回應；停止、逾時或超過顯示限制時均不自動重送。

對話只保存在目前頁面記憶體，重新載入即清除；請求仍會送往上游，產生正常用量及服務統計。失敗或取消的問答不加入後續上下文。Markdown 經 HTML 清理，不載入回覆中的外部圖片。

### 金鑰與即時監看

依 API 金鑰查看請求密度、Token 消耗、使用模型等級、正文與推理比例，協助調整資源配置。可選擇觀察時間與顯示欄位。

選用的「低推理降級」功能預設關閉，可對符合條件的高頻低推理用量限制候選模型品質等級；不覆寫明確指定模型或強制來源。若無合適候選，仍可能選用較高等級模型以維持可用性。近期監看樣本在重啟後重新累積，月次統計另行保存。

## 對話連續性與故障處理

### Codex 圖片轉接

Codex 圖片生成／編輯雖回傳 JSON，內部採 SSE，因此不套用一般非串流請求的整筆固定逾時。等待標頭及串流無活動逾時仍依 Provider 的逾時秒數，上游心跳會更新活動時間；客戶端取消仍會中止請求。此處不新增自動重試，也無法延長外部 MCP 客戶端或反向代理自行設定的逾時。

新版 App 相容處理：API 層在圖片／多媒體轉送前統一路徑，因此 `/backend-api/codex/images/...` 與帶部署前綴的路徑不會漏掉專用轉接。Codex 圖片編輯支援 multipart 的 `image`／`image[]`（最多 16 張）與 PNG `mask`，以及 JSON `images[].image_url`／`mask.image_url`；圖片可使用資料 URL 或經出站安全檢查的遠端 URL。帳號專屬 `file_id` 尚未建立所有權路由，會明確拒絕而非跨帳號轉送。

`X-Codex-Imagegen-Request-Id` 會轉送供追蹤；`X-Codex-Turn-State` 僅在持久化路由已驗證原 Provider 時轉送，重建歷史／改綁時清除，不能靠客戶端自報 Provider 授權。模型清單（含 AUTO）統一宣告 `prefer_websockets: false`，符合目前只提供 HTTP/SSE 的代理能力；本次沒有新增 WebSocket 支援。OAuth 圖片編輯採 Responses hosted image tool 轉接，是否獲上游接受仍需部署後驗證，並非對私有 Images 端點的實測相容承諾。

Codex 圖片生成與編輯轉接預設使用 `gpt-image-2` 作為圖片工具模型；Responses 主模型統一使用 Provider 的預設模型（模型清單第一筆），OAuth 與 API Key 路徑一致。預設模型未設定、為 AUTO 或圖片專用模型時會明確回報設定錯誤，不另選模型。`MARS_CODEX_IMAGE_MAIN_MODEL` 不再生效。

`gpt-image-2-2k`／`gpt-image-2-4k` 是本地別名，分別映射為 `2048x2048`／`3840x2160`；明確的 `size` 優先。驗證 GPT Image 2 的尺寸、像素總數、比例與品質設定，不送出 `input_fidelity`。圖片請求套用標頭逾時及 SSE 無活動計時，上游心跳更新活動時間；錯誤保留 HTTP 狀態、錯誤代碼及 Retry-After，沿用既有冷卻策略。不新增自動圖片重試，且必須收到 `response.completed` 才回傳成功，避免把斷線前的資料誤認為完整結果。

### 選路與重試

模型選路無候選時，未綁定 Provider 的指定模型可備援到符合能力與 token 上限的已設定模型；若原模型僅暫時冷卻或满載，仍等待原候選。AUTO 可在最後一層備援忽略分析器推導的 `long_context` 標記，但仍檢查實際 token 上限、使用者明確要求的能力，以及工具／圖片等必要能力。備援不繞過停用、停機、冷卻、併發與綁定限制，無健康相容來源時仍回報無可用來源；選路原因保留 fallback 紀錄。

「進階 → 全站流量保護」提供三個預設關閉的獨立 Switch，與既有「保存長時間配額冷卻」一起管理；儲存後生效，標題可立即顯示提示泡泡。

- **全站發送速率**：所有 Provider 推論合計至少間隔 5 秒，無突發額度。
- **全站併發**：上限為啟用且未處於停機時段的對話 Provider 帳號條目數 × 2（依來源 ID 去重，排除分類器及空端點；一般冷卻不影響計數）。這是共用總額度，不強制每帳號各占 2 條，各 Provider 自己的上限仍有效。沒有啟用來源時保留 2 條直連診斷額度；來源設定重載或進出停機時段會重新計算，上限降低不取消既有連線，待名額釋放才放行。
- **冷卻單筆探測**：來源或模型冷卻期間保守地限制整個 Provider；到期後只允許一條推論連線，正式代理確認冷卻後開始的請求成功才解除限制。較早開始、等待到冷卻結束的成功請求不解封，下一筆仍為單筆探測；直連診斷不解封。

上述保護共用程序內發送閘門，包含正式代理、重試與直連診斷，不含帳務／用量查詢；不跨服務副本同步，也不承諾 FIFO。開啟任一項後，發送閘門單次等待依「累計冷卻等待上限」限制，與選路等待分開計算；逾時不送上游、不懲罰 Provider。關閉開關不會取消既有連線，也不清除排程器原本的冷卻及每來源 10 秒發送間隔。

- **優先維持原配對**：一般故障沿用原來源；容量失敗且安全條件成立時，可在既有總預算內改用其他帳號。
- **容量備援有邊界**：已送出內容、強制指定來源，或需靠舊回應識別才能接續時，不跨帳號重播。可恢復的完整歷史保留訊息及工具結果，移除不能跨帳號使用的推理項目。
- **工具接續沿用原來源**：依呼叫端提供的對話識別恢復配對，降低跨帳號接續造成的問題。
- **心跳不是內容**：等待時維持下游連線，初始化與保活事件不會提前讓請求失去重試機會。
- **保活不代表重送**：上游完整 SSE 事件（包括 `keepalive` 與註解）重設上游無活動計時；代理自行送往下游的心跳不重設該計時、不增加上游請求，也不延長冷卻等待預算。收到 `response.failed` 後該次嘗試已結束，不能靠心跳恢復。
- **LIMITED 共用冷卻**：用量限制及 `rate_limit_exceeded` 解析 `resets_at`／`resets_in_seconds`，與 `Retry-After` 取較長等待時間；同一來源的排程共用冷卻，較短的新錯誤不縮短已有冷卻。沒有有效時間時沿用既有退避設定。
- **綁定來源有界排隊**：原 Provider 滿載或冷卻時，正式代理的來源選擇等待每個綁定來源最多容納 32 筆，不因滿載自行改綁；等待時間依後台累計等待上限並跨重連保留。等待不占上游併發名額，取消、取得名額或結束時釋放等待席位；排滿回 HTTP 429，已開始串流則回失敗事件。此上限為程序內防護，不是跨部署共用佇列，也不保證 FIFO；直連診斷不走此排程。
- **即時逐字串流**：Codex Responses 隨上游產出轉送文字及工具事件，不等待整筆回應完成；內容送出後，不在同一條串流內重新生成。
- **有限等待**：過載優先遵守 `Retry-After`；未提供時依 30、60、90 秒退避，後續 90 秒封頂，另加不到 1 秒的隨機偏移，等待及重試均有上限。
- **發送節流**：同一 Provider 推論請求至少間隔 10 秒，最大併發仍限制同時上游連線；跨 Provider 容量備援等待 30 秒，一般錯誤退避為 15、30、45、60 秒封頂。已驗證的相同請求即使沒有對話 ID，也會共用重連額度。
- **分開保留等待額度**：首次送出前的排隊、失敗後的退避各自累計，預設各 30 秒，避免排隊先耗盡重試等待空間；不增加上游嘗試次數。
- **限制重連放大**：已驗證且帶穩定對話識別的 Responses 請求，在重連後共用重試額度與兩階段等待紀錄；相同請求不重複並行送往上游。失敗紀錄保留 10 分鐘，成功或服務重啟後清除。
- **容量拒絕與節流分開處理**：尚未送出內容的容量拒絕退回工作重試額度，但不清除實際探測次數、已嘗試來源及等待紀錄。容量備援不另加工作額度冷卻，仍受短時間探測上限與上游冷卻限制。
- **冷卻後自動探測**：其他嘗試耗盡額度時暫停 30 秒，再給一次恢復探測。重連遇到代理冷卻時，在等待上限內保留連線並自動接續，不把「稍後重試」當成已完成回應。無法繼續等待時回 HTTP 429 與 `Retry-After`；已開始串流則回報失敗。綁定、上游冷卻及工具防重播限制不變。
- **工具防重播**：已交付完成的工具呼叫後中斷，重連時以助理通知提醒確認工具結果，不重送上游。只有文字、推理摘要或未完成工具參數時，不因此封鎖重連，仍遵守額度與冷卻；可能重複顯示內容。
- **保存與恢復配對**：重新啟動可讀取持久化綁定，透過「系統更新」升級前另保存路由快照。
- **設定重載不中斷計數**：同一來源共用活躍名額及執行狀態，既有請求完成後仍能正確歸還名額、更新統計；改變認證設定或端點時不混用舊狀態。

若用戶端未提供明確的提問回合識別，系統會保守固定整段對話，不保證每個新問題都重新分配 Provider。綁定遺失時，只有不依賴舊回應參照且歷史完整的請求才可能重新配對恢復問答；缺少的前文不能憑空重建。

這些功能不能消除上游過載、模型內部錯誤或網路斷線，也不保證工具只執行一次。即使尚未送出內容，上游仍可能已產生用量或執行操作。更新不能保存進行中的 TCP／SSE 連線；請在較少請求時更新，讓用戶端在重啟後重新連線。

詳見 [連線與重試](RETRY_POLICY.md) 與 [對話配對與更新恢復](TURN_BINDING.md)。

## 常見情況

### 顯示稍後重試，Agent 卻停下來

已完成回應中的「稍後重試」只是文字，不會替 Agent 安排下一次請求。新版對符合跨重連追蹤條件的 Responses 請求，在重連入口遇到代理冷卻時，可於等待上限內保留連線，到期後自動取得探測資格；不保證上游一定恢復，也不會讓已結束的舊回應自行繼續。

若回應已結束，需由用戶端重新連線或手動提出接續請求。收到工具防重播通知時，先確認工具是否已完成，再提供結果接續，避免重複執行。用戶端的「重新連線 1/5」不是代理剩餘嘗試次數。

### 可使用量長時間沒有變

先查看各帳號的資料來源、成功時間及失敗狀態，不只看總平均。成功時間持續更新而比例相同，可能是上游資料尚未變動；成功時間停住或標示「含舊值」，則需檢查帳號查詢狀態。系統保留最後有效值，不以缺值補成滿額，也不推估尚未觀測到的消耗。

每日配額消耗與 Token 統計分開計算；缺少有效觀測時，每日用量可能不完整，不能把未增加的數字解讀為完全沒有使用。

### 帳號用量不平均

均衡主要在新配對時生效，不搬移既有回合來追平百分比。長回合、指定來源、不同額度窗口或暫時冷卻，都可能使帳號用量出現差距；請同時查看綁定數、活躍數與用量新鮮度。

## 接入方式

將相容工具的 Base URL 設為 `https://<你的服務位址>/v1`，使用管理介面核發的 API 金鑰。以下為格式範例，模型與功能仍以所選來源支援為準。

### Chat Completions

```http
POST /v1/chat/completions
Authorization: Bearer <client-token>
Content-Type: application/json

{"model":"AUTO","messages":[{"role":"user","content":"請整理這份文件"}],"stream":false}
```

### Responses

```http
POST /v1/responses
Authorization: Bearer <client-token>
Content-Type: application/json

{"model":"AUTO","input":"請分析這個專案","stream":true,"prompt_cache_key":"project-session"}
```

同一任務保持穩定的對話識別。以 `previous_response_id` 接續時，仍須使用保存該回應的原來源。另支援回應查詢、取消、刪除及輸入項目等相容子路由。

### MCP

端點為 `http://<host>:<port>/mcp/`。可在「設定 > MCP」查看工具清單、開關、唯讀模式與允許的瀏覽器來源。

API 金鑰可供一般 API 與 MCP 使用；MCP 專用金鑰僅限 MCP；Web 管理登入不作為 MCP 認證。金鑰管理與帳單等受限操作不透過 MCP 公開。對外開放前，請先確認所核發金鑰允許的操作範圍。

### Codex 設定整合

既有設定工具可合併 Provider、模型目錄及相關功能至 `config.toml`，保留專案信任與不相關的個人設定，並提供恢復原來源的方式。部署 ZIP 不包含這些設定腳本。

套用或還原後，請完整重新啟動 Codex App、CLI 或 VS Code Extension Host。設定方式與既有環境變數名稱請見 [安裝說明](install.md#codex-app-用戶端設定)。
